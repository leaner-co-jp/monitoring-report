# 出力ルール・日本語表現・検証チェック

## 出力ルール

- **数値はすべて単位付き**（ms, %, req, MiB / GiB）。
- 比較は「今週: X / 先週: Y / 差分: ±Z（±W%）」。
- 推測・主観は `(推定)` を付けて事実と分離する。
- データ取得に失敗した場合は `⚠️ 取得不可: <理由>` と明示する（省略不可）。

### 出力構成（テンプレート §1〜§3）

構成の規則（2階層・5原則・空枠の扱い・色の決め方）は `templates/report.md` 冒頭の運用ガイドが唯一の定義。手順側が付け加えるのは1点だけ:

- monitor が鳴っていない（または monitor が存在しない）指標で先週比 ±20% 以上動いたものは §1 の「monitor 以外で動いた指標」に書く。monitor のカバレッジの穴に気付く唯一の入口なので**省略不可**。発火回数の増減を書くときは必ず分母（閾値超過サンプル数／総サンプル数）と最長継続時間を併記する（分母なしの「N倍」は書かない）。

### 必ず出力するもの

レポートに**必ず載せる**。テンプレートの説明文に見えても、これらは成果物の一部である。

- 固定形式のタイトル
- `## 🔗 調査リンク`（タイトル直後）
- §1〜§3 の見出し構造（文言・順序・階層をテンプレートどおりに）
- **「色の意味」の導入文と表**（固定文。そのまま出力する）
- **「評価ルール」の導入文と規則1〜4、および規則4の但し書き**（固定文。そのまま出力する）
- ドメイン文脈を伝える注記 — §2 冒頭の「調査時の前提」、§3.1 の IOPS・ALB の運用注記、FJ の elb 防御シグナルなど

### 絶対に出力しないもの

- `templates/report.md` 冒頭の運用ガイド（トグル全体）
- 「ガイド:」で始まる記入指示（各節にぶら下がっているトグル）
- プレースホルダの書き方の説明
- 執筆者向けの方法論・編集指示
- 「以下を出力しない」のような、テンプレート利用者に向けた文

<aside>
⚠️

**「方法論の前置きを除外」は、固定文の「色の意味」「評価ルール」には適用しない。**

除外対象は、テンプレートがエージェントに向けて書いている枕文（「monitor 駆動の OODA レポート…」のような、成果物の一部でない説明）だけである。§1 の「色の意味」と「評価ルール」は、**読者に判定基準を示すための固定文であり、毎週そのまま出力する**。見出しに「固定文。そのまま出力する」と明記してあるものは、方法論の説明に見えても必ず残す。

</aside>

出力はタイトル行（`# …`）から開始する。前置きの引用文は付けず、**タイトル → `## 🔗 調査リンク` → `## 1. 🎯 総合評価`** の順で続ける。

### 調査リンク規約（Decide / Act と各 finding に添える）

site は `app.datadoghq.com`、markdown の `[ラベル](URL)` 記法。具体形はテンプレート冒頭の「🔗 調査リンク」。

- **期間レンジを見せる用途はダッシュボード**: `/dashboard/{{P.dashboard}}?from_ts={{F}}&to_ts={{T}}`（epoch ms）。広いウインドウを確実に反映する。
- **特定インシデント時刻の点的な調査はトレース探索**: `/apm/traces?...&end={{incident_epoch_ms}}&paused=true`。⚠️ `/apm/traces` は `storage=hot` のため**広い `start` を無視し、end − 15分にクランプ**する → インシデント時刻に `end` を合わせ、15分ウインドウで使う（週レンジには使わない）。`&paused=true` でウインドウを固定する。
- **週全体で重い endpoint / resource を順位付けする**なら APM サービスページ: `/apm/services/{{P.api_service}}?env=production&start={{F}}&end={{T}}`（Rails）/ `.../{{P.worker_service}}`（Job）。
- **monitor は名前・リンク・ID の合わせ技で書く**: `[<monitor 名>](https://app.datadoghq.com/monitors/{{monitor_id}})（#{{monitor_id}}）`。本文で monitor に言及するときは `mon 12345` のような ID 単独の略記を使わず、必ずこの形でクリックでき・一意に特定でき・人間が読んで分かる3点を満たす。
- アラートイベント本文の埋め込みリンクと `get_datadog_metric` 応答の `metrics_explorer_url` は **Datadog 生成のため再利用が最も安全**。手組みより優先する。

## レポートの日本語表現

レポートは**自然な日本語**を心がける（英語・カタカナの直訳調を避け、読み手が日本語として無理なく読める表現にする）。例:

| 修正前（違和感あり） | 修正後 |
| --- | --- |
| sustained peak (1h) / 1h sustained peak | 1時間平均の持続ピーク／1時間平均でならした持続的なピーク |
| sustained は低位 | 持続的な使用率は低位 |
| sustained な劣化 | 持続的な劣化 |
| critical 閾値をクロス / critical をクロス | critical 閾値を超過／突破 |
| 瞬間バースト / 大量バースト | 瞬間的な集中／短時間に大量実行 |
| latency は…と軽く | 処理時間は…と軽く |

<aside>
📌

技術用語を無理に訳す必要はない。monitor 状態の英語（OK / Warn / Alert）や固有名詞（monitor 名・メトリクス名・`resource_name`）はそのまま使ってよい。地の文が英語直訳調にならないようにするのが狙い。

</aside>

## 書き込み前の検証チェック

Notion に書き込む**前に**、合成した完成成果物に対して次を全部確認する。
満たしていない項目は書き込む前に直す（直せないものは §3.3 に理由を書く）。

機械的に検出できる項目は、スクリプトで一度に確認できる。

```bash
python3 scripts/validate-report.py <完成成果物.md> --product <lp|pu|fj> [--fired|--no-fired]
```

### 必須の出力構造

次の見出しが**すべて**存在すること。1つでも欠けたら書き込まない。

- タイトルが `YYYY/MM/DD - MM/DD {{P.report_title}}` の固定形式に一致
- `## 🔗 調査リンク`
- `## 1. 🎯 総合評価`
- `### 色の意味（レポート全体で共通 / 固定文。そのまま出力する）`
- `### 評価ルール（レポート全体で共通 / 固定文。そのまま出力する）`
- `### 総合ステータス`
- `### 今週のシグナル変化（先週比）`
- `### 先週比の主要変化`
- `### Decide / Act 候補（人間判断用）`
- `### 報告の結び`
- `## 3. 📎 付録（記録用）`
- `### 前回 Decide / Act の反映状況`
- `### 3.1 全指標の週次記録（台帳）`
- `### 3.2 取得時刻・期間`
- `### 3.3 今週の取得上の注記`

§2 は発火の有無と一致していること。

- 今週 monitor の発火が**ある** → `## 2. 🔍 調査` が**存在する**
- 今週 monitor の発火が**ない** → `## 2. 🔍 調査` が**存在しない**（「該当なし」の見出しすら出さない）

### 内容の検査

- `{{P.` / `{{P:` が1つも残っていない（テンプレート合成の取りこぼし）
- 未置換の一般プレースホルダ（`{{ … }}`）が残っていない
- 「ガイド:」で始まる記入指示が出力に混ざっていない
- 「色の意味」の表と「評価ルール」の規則1〜4が、固定文のまま入っている
- §3.1 台帳の**各行に「校正メモ」が書かれている**（該当なしの行も空欄のまま出さない）
- 取得できなかった箇所すべてに `⚠️ 取得不可: <理由>` があり、**理由が書かれている**
- monitor の発火の事実に色を付けていない（件数と継続時間で書いている）
- §1 の「monitor 以外で動いた指標」が埋まっている（該当なしなら「該当なし」）
- 前週の Decide / Act 候補の反映状況が §3 に書かれている（確認できなかった場合はその理由）
- 期間が {{P.window_ja}}の JST 7日間（直近のクローズ済み7日間）になっている

## 書き込み後の検証

書き込んだら、**Notion から対象ページを再取得して**次を確認する。
書きっぱなしにしない（変換の過程で見出しが落ちることがある）。

- タイトルプロパティが固定形式どおり
- 見出しの構造と並びが完成成果物と一致
- 固定ブロック（色の意味の表、評価ルールの規則1〜4、報告の結び）が残っている
- §3.1 台帳の表が、列と行を保ったまま入っている

**再取得での検証に失敗したら、成功と報告しない。** 何がどう一致しなかったかを具体的に述べる。
既存ページを更新した場合も同じ検証を行う。

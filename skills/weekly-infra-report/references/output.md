# 出力ルール・日本語表現・検証チェック

## 出力ルール

- **数値はすべて単位付き**（ms, %, req, MiB / GiB）。
- 比較は「今週: X / 先週: Y / 差分: ±Z（±W%）」。
- 推測・主観は `(推定)` を付けて事実と分離する。
- データ取得に失敗した場合は `⚠️ 取得不可: <理由>` と明示する（省略不可）。

### 出力構成（テンプレート §1〜§3）

構成の規則（2階層・5原則・空枠の扱い・色の決め方）は `templates/report.md` 冒頭の運用ガイドが唯一の定義。手順側が付け加えるのは1点だけ:

- monitor が鳴っていない（または monitor が存在しない）指標で先週比 ±20% 以上動いたものは §1 の「monitor 以外で動いた指標」に書く。monitor のカバレッジの穴に気付く唯一の入口なので**省略不可**。発火回数の増減を書くときは必ず分母（閾値超過サンプル数／総サンプル数）と最長継続時間を併記する（分母なしの「N倍」は書かない）。

### 出力時に必ず除外するもの

1. `templates/report.md` 冒頭の運用ガイド（トグル）
2. テンプレートの methodology 前置き（「monitor 駆動の OODA レポート…」等の枕文）
3. 「ガイド:」で始まる記入指示、書き方だけを指示する注記

**残すもの**: ドメイン文脈を伝える注記は中身なので残す。Sentry 棲み分けと IOPS 注意（§2 冒頭の「調査時の前提」と §3.1 の注記）、FJ の elb 防御シグナルなど。

出力はタイトル行（`# …`）から開始し、前置きの引用文を付けずそのまま `## 1` へ続ける。

### 調査リンク規約（Decide / Act と各 finding に添える）

site は `app.datadoghq.com`、markdown の `[ラベル](URL)` 記法。具体形はテンプレート冒頭の「🔗 調査リンク」。

- **期間レンジを見せる用途はダッシュボード**: `/dashboard/{{P.dashboard}}?from_ts={{F}}&to_ts={{T}}`（epoch ms）。広いウインドウを確実に反映する。
- **特定インシデント時刻の点的な調査はトレース探索**: `/apm/traces?...&end={{incident_epoch_ms}}&paused=true`。⚠️ `/apm/traces` は `storage=hot` のため**広い `start` を無視し、end − 15分にクランプ**する → インシデント時刻に `end` を合わせ、15分ウインドウで使う（週レンジには使わない）。`&paused=true` でウインドウを固定する。
- **週全体で重い endpoint / resource を順位付けする**なら APM サービスページ: `/apm/services/{{P.api_service}}?env=production&start={{F}}&end={{T}}`（Rails）/ `.../{{P.worker_service}}`（Job）。
- **monitor は名前・リンク・ID の合わせ技で書く**: `[<monitor 名>](https://app.datadoghq.com/monitors/{{monitor_id}})（#{{monitor_id}}）`。本文で monitor に言及するときは `mon 12345` のような ID 単独の略記を使わず、必ずこの形でクリックでき・一意に特定でき・人間が読んで分かる3点を満たす。
- アラートイベント本文の埋め込みリンクと `get_datadog_metric` 応答の `metrics_explorer_url` は **Datadog 生成のため再利用が最も安全**。手組みより優先する。

## レポートの日本語表現

レポートは**自然な日本語**を心がける（英語・カタカナの直訳調を避け、読み手が日本語として無理なく読める表現にする）。例:

| 修正前（違和感あり） | 修正後 |
| --- | --- |
| sustained peak (1h) / 1h sustained peak | 1時間平均の持続ピーク／1時間平均でならした持続的なピーク |
| sustained は低位 | 持続的な使用率は低位 |
| sustained な劣化 | 持続的な劣化 |
| critical 閾値をクロス / critical をクロス | critical 閾値を超過／突破 |
| 瞬間バースト / 大量バースト | 瞬間的な集中／短時間に大量実行 |
| latency は…と軽く | 処理時間は…と軽く |

<aside>
📌

技術用語を無理に訳す必要はない。monitor 状態の英語（OK / Warn / Alert）や固有名詞（monitor 名・メトリクス名・`resource_name`）はそのまま使ってよい。地の文が英語直訳調にならないようにするのが狙い。

</aside>

## 書き込み前の検証チェック

Notion に書き込む**前に**次を全部満たしているか確認する。満たしていない項目は書き込む前に直す（直せないものは §3.3 に理由を書く）。

- `templates/report.md`、`templates/<product>.md`、この `output.md` の出力に必要なブロックを確認済み
- 直近の前週レポートを確認し、タイトル形式・見出し順・固定文・表構造を比較済み
- 上記の確認が出力上限で途切れた場合は元ソースを分割して再読済み（未確認のまま独自の要約形式で出力しない）
- **出力に `{{P.` / `{{P:` が1つも残っていない**（テンプレート合成の取りこぼしがない）
- ページタイトルが固定形式で、期間が **{{P.window_ja}}の JST 7日間**（直近のクローズ済み7日間）になっている
- 出力先 DB を作成日時 DESC で確認し、同じウインドウの同名ページが**存在しない**（あれば新規作成せず findings のみ報告）
- 構成が **§1 / §2 / §3** のテンプレートどおり
- **今週の発火がゼロなら §2 が存在しない**（「該当なし」の見出しすら出していない）
- monitor の発火の事実に**色を付けていない**（件数と継続時間で書いている）
- §1 の「monitor 以外で動いた指標」が埋まっている（該当なしなら「該当なし」）
- §3.1 の台帳に必須行がすべてあり、「校正メモ」列が毎行埋まっている
- 取得できなかった箇所すべてに `⚠️ 取得不可: <理由>` があり、**理由が書かれている**
- 前週の Decide / Act 候補の反映状況が §3 に書かれている（確認できなかった場合はその理由が書かれている）
